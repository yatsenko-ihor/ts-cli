RUN PANEL [2]
─────────────
  Everything you can execute on the selected machine, in three tabs
  ([ / ] or h / l switch tabs):

  Scripts   Local files from ~/.ts-cli/scripts/. Any executable file
            works; the interpreter comes from its shebang (no shebang
            = sh). The script is streamed over one SSH connection into
            a private temp file, run, and removed. Optional header:
              # ts-cli: name=Disk usage
              # ts-cli: desc=Largest directories under /
              # ts-cli: os=linux,darwin      (hide on other OSes)
              # ts-cli: args=path,depth      (asked before running)
            r reloads the list.

  Commands  Saved named commands kept in config.json. {{name}}
            placeholders are asked for at run time.
            n new • e edit • d delete.

  Recent    What ran on this machine before, newest first.
            enter runs again • s saves as a Command • d forgets it.

  :         Ad-hoc command line, works from any tab and from the
            machine list. Enter runs it immediately.

  Several machines:
            Mark machines with Space (or * for all). The Run panel and
            ":" then target the whole set, in parallel (8 at a time),
            without prompts: saved username/password or the default
            username. Offline machines, machines without a username,
            from another account, or not matching the script's os= are
            skipped with a reason; a rejected key/password is reported
            as failed — connect once with s to save credentials.

OUTPUT PANEL [3]
────────────────
  Output streams in while the job runs; the title shows "● running",
  then "✓ exit 0" or "✗ exit N" with the elapsed time. For several
  machines each one has its own section with its status in the header
  and the title summarises "3/4 done · 1 failed · 1 skipped".
  ↑/k ↓/j move • g/G top/end (G re-enables auto-follow)
  {/} previous/next machine (multi-machine runs)
  c copy line as absolute remote path • n (N in multi) copy file name
  x (or Ctrl+C) stop the running job(s) • C clear

SSH CREDENTIALS
───────────────
  Default username:
    After your first successful SSH connection, the username is saved
    globally as the default. This is NOT the OS username — it's the
    value saved after first successful connect. All new machines use
    this default until overridden per-machine.

  Per-machine passwords:
    Each machine stores its own unique encrypted password, keyed by
    the device's Tailscale ID (renaming a machine keeps its login).
    Nothing is saved until a connection succeeds. A saved password is
    forgotten only when sshpass reports it was rejected; an ordinary
    non-zero exit of the remote shell keeps everything.

  Connection flow (sessions, commands and scripts alike):
    1. Saved password → connect directly, no prompt
    2. No saved password → try key-based auth first
       (username: per-machine → default → ask)
    3. Auth fails → ask for the password, retry with sshpass
    4. Success → save username (+ password if entered). A typed
       password is verified first with a quick login and saved right
       away, so a session that later drops never loses it
    5. Saved password rejected → forget it, ask again
    6. Still failing → retry menu (change user/pass/both)

STATUS AND PING
───────────────
  Colour = Tailscale API baseline (connectedToControl, or last seen
  < 5 min), refined by `tailscale ping`, which wins in both directions:
  a reply = 🟢 usable, no reply = ⭕️ unreachable.
  Pings run: with p; and as a ≤2 s pre-flight check before s /
  running something on one machine (Esc cancels). Background ping of
  the machine under the cursor exists but is currently switched off.
  Machines of another Tailscale account are never auto-pinged.

ICONS
─────
  Symbols (default; emoji style: F12 → Icon style)
  ●  green   Device is reachable (API online or answered a ping)
  ●  red     Device is offline (last seen > 5 min ago)
  ○  yellow  Last ping got no reply: treated as unreachable
  pw         A password is saved for this machine
  exp        Device key has expired (red)

  Emoji style
  🟢  Reachable      🔴  Offline      ⭕️  Last ping got no reply
  🔐  Password saved                  🔒  Device key has expired

  Other
  🔑  Device key expires in the future (device list)
  🔑  Key-based auth, no password stored (credentials list)
  ⚠️   Key expiry warning

OPTIONS MENU (o)
────────────────
  Machines with saved passwords:
    View/delete per-machine SSH credentials.
    Press 'd' to delete a machine's saved credentials.

  Encryption key:
    Move the master key between ~/.ts-cli/key and the OS keychain
    (macOS Keychain / Linux Secret Service / Windows Credential
    Manager). Same as `ts-cli secrets use keychain|file`.

ENCRYPTION
──────────
  SSH passwords and Tailscale API keys are encrypted with AES-256-GCM
  using one random master key. By default the key is in ~/.ts-cli/key
  (mode 0600); with the keychain option it is held by the OS and never
  written under ~/.ts-cli, so a copied config directory alone cannot be
  decrypted. If the keychain is unreachable (headless session), the key
  file is used when it still exists and a warning is shown. The SSH
  password is passed to sshpass over a private file descriptor and
  never appears in the process list.
