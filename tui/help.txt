SSH CREDENTIALS
───────────────
  Default username:
    After your first successful SSH connection, the username is saved
    globally as the default. This is NOT the OS username — it's the
    value saved after first successful connect. All new machines use
    this default until overridden per-machine.

  Per-machine passwords:
    Each machine stores its own unique encrypted password, keyed by
    the device's Tailscale ID (renaming a machine keeps its login).
    Nothing is saved until a connection succeeds. A saved password is
    forgotten only when sshpass reports it was rejected; an ordinary
    non-zero exit of the remote shell keeps everything.

  Connection flow (sessions and remote commands alike):
    1. Saved password → connect directly, no prompt
    2. No saved password → try key-based auth first
       (username: per-machine → default → ask)
    3. Auth fails → ask for the password, retry with sshpass
    4. Success → save username (+ password if entered)
    5. Saved password rejected → forget it, ask again
    6. Still failing → retry menu (change user/pass/both)

OPTIONS MENU (o)
────────────────
  Machines with saved passwords:
    View/delete per-machine SSH credentials.
    Press 'd' to delete a machine's saved credentials.

ENCRYPTION
──────────
  Passwords are encrypted with AES-256-GCM using a random key stored
  in ~/.ts-cli/key (mode 0600), separate from config.json. Anyone who
  can read your home directory can read both files, so protect
  ~/.ts-cli/ like ~/.ssh/. The password is passed to sshpass over a
  private file descriptor and never appears in the process list.
